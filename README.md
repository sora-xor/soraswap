# SoraSwap

SoraSwap is an Apache-2.0 Kotodama smart-contract repository for Sora Nexus. It uses the sibling [`../iroha`](../iroha) checkout as the canonical compiler, IVM runtime, CLI, and Torii toolchain.

Current status:
- Repo scaffold is in place.
- Initial Kotodama contracts are present for `n3x`, DLMM, launchpad, referral, automation, farms, perps, options, and cover.
- DLMM is treated as the deployable AMM surface.
- The `n3x` basket hub now supports configurable basket targets, mint and redeem fees, redeem quoting, and mirrored fee accounting.
- The DLMM pool scaffold now executes guarded multi-bin swaps, seeds multiple bins deterministically, and supports explicit `position_id` LP records with per-bin fee claims.
- The launchpad scaffold now tracks recorded allocations, configurable vesting windows, claim inventory, refunds, explicit seed inventory, and registered DLMM seed plans in a single contract.
- The remaining DeFi app contracts now expose explicit single-contract lifecycles with typed `view fn` snapshots: routed referral splits, executor-bound recurring automation schedules, farm reward budgets, perps risk/collateral flows, options expiry tracking, and sized cover policies.
- The current DLMM LP surface is a single-contract scaffold, not the final helper/NFT wrapper layout.
- `xor#universal` is the canonical base asset for routing and pool pricing.
- Advanced parity work is still being ported and is tracked in [`docs/parity/migration_register.md`](./docs/parity/migration_register.md).

## Layout
- `contracts/` - Kotodama contracts grouped by module.
- `scripts/` - compile, lint, deploy, and smoke wrappers around `../iroha`.
- `tests/` - end-to-end local verification wrappers that keep the localnet alive for the duration of the run.
- `config/` - local and testnet client templates.
- `docs/` - parity, interface, and state-layout notes.
- `artifacts/` - generated bytecode and manifests.
- `deployments/` - deployment evidence, canonical address records, and manifests by environment.

## Asset and Naming Policy
- Base asset: `xor#universal`
- Stable basket brand: `n3x`
- Helper aliases under this repo: `usdt#soraswap.universal`, `usdc#soraswap.universal`, `kusd#soraswap.universal`, `n3x#soraswap.universal`

## Requirements
- A sibling `../iroha` checkout.
- Rust toolchain able to build `iroha`, `ivm`, and `irohad`.
- `curl` and `jq` for Torii smoke calls and response checks.
- A client config for either local Nexus or `taira.sora.org`.

## Local Nexus
`scripts/local_up.sh` generates and starts a fresh one-peer Kagami localnet in `tmp/iroha-localnet` using the sibling `../iroha` checkout and the Nexus/NPoS profile. It now also injects a SoraSwap-specific IVM stack profile into the generated peer config so DLMM swap smoke runs with an `8 MiB` guest stack budget by default. When another local Nexus is already running, set `SORASWAP_LOCALNET_DIR`, `SORASWAP_LOCALNET_BASE_API_PORT`, and `SORASWAP_LOCALNET_BASE_P2P_PORT` to spin up an isolated verification localnet instead of reusing the default one.

Default local client config:
```bash
tmp/iroha-localnet/client.toml
```

Local bootstrap also acquires the `soraswap` SNS domain-name lease before registering the on-ledger `soraswap` domain, which is now required by current Nexus core. It then binds and tops up `xor#universal` as the base asset alongside the repo helper assets.

`make deploy-local` now also runs `scripts/bootstrap_contract_state.sh` after activation so the foundational contracts have usable local state before smoke calls. The bootstrap is skip-and-verify: singleton init/config writes are skipped when their typed config views already match, and the DLMM seed block is only replayed when the current bin and position snapshots are still pristine. Each deploy also writes `deployments/local/<contract>.deploy.json` with the current deployment evidence for that contract.

`make smoke-local` now writes a machine-readable report to `deployments/local/smoke.latest.json` and a timestamped copy. That report separates committed mutation transaction hashes from typed `/v1/contracts/view` results and records decoded integer snapshots for the `n3x`, deployable DLMM, launchpad, referral, farms, perps, options, cover, and automation surfaces. The `n3x` section now includes configured fee and target state, the launchpad section includes both sale-level claim/seed aggregates plus allocation refund state, the referral section includes routed child-plus-parent settlement state, and the automation section includes executor-bound recurring schedule state.

## Public Testnet
The public testnet template lives at:
```bash
config/testnet/taira.client.toml.example
```

Copy it to an untracked `.toml`, set the correct credentials, then point `SORASWAP_CLIENT_CONFIG` at that file before running `make deploy-testnet`.

As observed on March 25, 2026, live `taira.sora.org` still uses chain id `809574f5-fee7-5e69-bfcf-52451e42d50f`. If Taira is redeployed with a new chain id, update your copied client config before running any deploy or smoke flow.

`make deploy-testnet` now treats public deployment as an address-first `universal` dataspace flow. Before deploying it fingerprints the live chain using `torii_url + chain id + block 1 hash`, writes `deployments/testnet/chain.latest.json`, and archives stale `deployments/testnet` evidence under `deployments/testnet/archive/<utc>-<block1-hash>/` whenever Taira has been redeployed without changing the chain id. Current deploy state is recorded in `deployments/testnet/deploy.latest.json`, and each `*.deploy.json` record stores the canonical `contract_address`, `deploy_nonce`, and `chain_fingerprint`.

`scripts/fund_testnet_signer.sh` is the operator helper for public Taira funding. `make deploy-testnet` will auto-claim faucet funds when the signer is missing or unfunded, solve the faucet PoW puzzle, and wait for a positive `xor#universal` balance before deploying. `make smoke-testnet` is intentionally non-destructive: it does not auto-fund, and instead prints the exact `scripts/fund_testnet_signer.sh` command when the signer is not ready.

`make smoke-testnet` checks the expected canonical contract addresses are active in the `universal` dataspace, compares live code hashes against any saved deployment manifests, runs non-destructive `n3x` and DLMM router view calls, then executes contract-native initialization assertions plus typed view snapshots before writing `deployments/testnet/smoke.latest.json`. Both `instances.latest.json` and `smoke.latest.json` include the current `chain_fingerprint` so reports can be tied back to a specific Taira reset.

On March 28, 2026, probing the live Taira node showed:
- chain id `809574f5-fee7-5e69-bfcf-52451e42d50f`
- `/v1/accounts/onboard` responding `403` with `UAID onboarding disabled`
- `/v1/accounts/faucet/puzzle` responding `200` once faucet is enabled on the public node
- `status.tx_gossip.caps.frame_cap_bytes` is expected to be at least `1048576` for routine SoraSwap deploys without split fallback
- public contract lifecycle writes were being rejected when Taira omitted an explicit `[nexus.fees]` block and fell back to the canonical default fee selector instead of `xor#universal`

Public SoraSwap docs and scripts now target canonical contract addresses in the `universal` dataspace. A Taira rollout must therefore include both the explicit `nexus.fees.fee_asset_id = "xor#universal"` override and the raised `network.max_frame_bytes_tx_gossip = 1048576` setting from `../iroha/configs/soranexus/taira/config.toml`, then a fresh `make deploy-testnet` run after the node comes back.

For a collision-free local full-stack check, use `make test-local-isolated`. It starts a dedicated localnet under `tmp/iroha-localnet-verify`, defaults to `18080` / `11337` instead of the main local ports, deploys the full contract set, runs the full `smoke_local.sh` mutation flow against the generated client config, asserts the exact post-smoke `n3x` and DLMM view snapshots, and tears the node back down. The same DLMM-oriented stack overrides are applied there by default, and the isolated permissioned wrapper now raises both Kagami timing knobs to `5000 ms` by default so the cold first-write `dlmm_pool` path stays clear of the 6 s quorum-timeout band seen on the debug localnet profile. Set `SORASWAP_RUN_TESTNET_SMOKE=1` if you also want the non-destructive `smoke_testnet.sh` compatibility pass in the same isolated run.

For a foundation-only deployability check, use `make test-local-foundation-isolated`. It exports both scope variables as `foundation`, proves the `n3x` plus DLMM bootstrap and smoke path on a dedicated permissioned localnet, and skips later-module initialization so unrelated launchpad/farms/perps/options scaffolds do not block DLMM verification.

## Notes
- The scripts are idempotent where practical and explicitly verify alias bindings before skipping asset registration.
- The local smoke now configures the `n3x` basket targets and fees, performs a real deposit-and-mint followed by quote-and-burn-and-redeem, and checks the signer’s `n3x#soraswap.universal` balance before and after.
- The local smoke also queries `n3x` and DLMM state through `view fn` snapshots after the mutation flow and asserts the expected post-smoke multi-bin DLMM reserves, share supply, and guard config after a position add, fee collect, and partial LP withdrawal before writing `deployments/local/smoke.latest.json`.
- In full scope, the local smoke also drives launchpad, referral, farms, perps, options, cover, and automation through their current single-contract lifecycle surfaces. The launchpad flow now covers recorded allocation claim settlement on a successful sale and refund settlement on a failed sale, the referral flow now covers routed child-plus-parent settlement, and the automation flow now covers executor-bound recurring dispatch plus reschedule before recording the resulting typed view snapshots in the same report.
- `make test-local-isolated` is the safest end-to-end verifier when another local Nexus is already running, because it avoids the default `tmp/iroha-localnet` path and the default local ports while still proving the post-swap local contract state.
- `make test-local-foundation-isolated` is the fastest isolated verifier for the current production target because it narrows the run to `n3x` plus DLMM and avoids unrelated downstream module bootstrap failures.
- The testnet smoke is intentionally non-destructive: it verifies live bindings plus quote paths without minting, swapping, re-seeding shared testnet state, or auto-claiming faucet funds.
- Mutating smoke steps require both a successful Torii submission and a committed transaction hash; read-only steps execute through `/v1/contracts/view`.
- The current contract set is a real Kotodama foundation, not full product parity. Use the parity register before treating a module as production-complete.
